tug works without any configuration. When you want to change a default, create
`config.yaml` in tug's config folder:

| Platform | Path |
| --- | --- |
| macOS and Linux | `~/.config/tug/config.yaml` (or `$XDG_CONFIG_HOME/tug/config.yaml`) |
| Windows | `%AppData%\tug\config.yaml` |
| With `TUG_HOME` set | `$TUG_HOME/config/config.yaml` |

tug reads the file strictly: a misspelt key is an error, so you'll know
straight away rather than wondering why a setting does nothing.

## A complete example

```yaml title="~/.config/tug/config.yaml"
# Where secrets live: auto, keychain or file.
keyring:
  backend: auto

# The kubectl to run for passthrough commands and tug top.
kubectl: kubectl

guard:
  # A cluster matching ANY of these label sets opens read-only.
  readOnlyLabels:
    - env: prod
    - team: payments
      tier: critical

plugins:
  # Built-in provider names a plugin may replace.
  allowOverride: []
  # Time limits per plugin operation.
  timeouts:
    list: 60s
    credential: 15s
    rotate: 2m

sessions:
  # Remove sessions untouched for this long.
  maxAge: 168h

oidc:
  # Where the browser comes back to after an OpenID Connect sign-in.
  listenAddresses: [127.0.0.1:8000, 127.0.0.1:18000]
```

## plugins

<TypeTable
  type={{
    allowOverride: {
      type: 'string[]',
      default: '[]',

    timeouts: {
      type: 'map of operation to duration',
      default: '{list: 30s, credential: 10s, rotate: 60s, others: 30s}',

  }}

## oidc

<TypeTable
  type={{
    listenAddresses: {
      type: 'string[]',

      description:
        'Loopback addresses tried, in order, for the browser’s return after tug auth login (it comes back to http://localhost:<port>). Change them only if your identity provider allows other redirect URLs.',
