## tug import

Find accounts on this machine and import their clusters. See
[Importing clusters](/docs/guides/importing).

```bash
tug import [provider] [kubeconfig files...] [flags]
```

| Flag | Meaning |
| --- | --- |
| `--account <id>` | Account to import. |
| `--set key=value` | Account setting. Repeatable. |
| `-y`, `--yes` | Import everything found without asking. |

```bash
tug import                          # scan every provider
tug import kubeconfig ./lke.yaml    # import a downloaded kubeconfig
tug import aws --account work --set regions=eu-west-1
```

Secrets a provider declares are asked for once and kept in the keychain. In
scripts, set `TUG_SECRET_<NAME>` (for example `TUG_SECRET_API_TOKEN`).

## tug sync

Refresh every imported source. New clusters are added; clusters gone upstream
are marked stale. Exits 1 if any source failed.

```bash
tug sync
```

## tug ls

List clusters in the catalog. Aliases: `tug clusters`, `tug list`. The cluster
this terminal is connected to is marked `*`.

```bash
tug ls [flags]
```

| Flag | Meaning |
| --- | --- |
| `-l`, `--selector <labels>` | Filter by labels, such as `env=prod,gpu=true`. |
| `-o`, `--output <format>` | `table`, `json`, `yaml` or `name`. |

Table columns: `NAME`, `PROVIDER`, `ACCOUNT`, `REGION`, `VERSION`, `ENV`,
`LABELS`, `STATUS`. JSON fields: `name`, `id`, `provider`, `account`,
`region`, `version`, `server`, `labels`, `stale`, `lastSeen`, and `aliases`
and `team` for a cluster a [team catalog](/docs/guides/teams) describes.

## tug label

Set or remove your own labels on a cluster. Needs the exact cluster name.
Your labels win over the provider's and survive `tug sync`.

```bash
tug label <cluster> key=value... | key-...
```

```bash
tug label staging-us env=staging team=payments
tug label staging-us team-
```

## tug forget

Remove an imported source, its clusters and their stored credentials.

```bash
tug forget <provider>/<account>
```

```bash
tug forget aws/work
```

## tug team

Follow [team catalogs](/docs/guides/teams): signed files in which a team
publishes names, aliases and labels for its clusters, provider accounts,
plugin indexes and safety policies. A team catalog holds no credentials and
grants no Kubernetes permission.

### tug team add

Fetch a team's catalog, check its signature, show what it can do and what it
would change, and ask before following it.

```bash
tug team add <name> <url> --public-key <key> [--yes]
tug team add <name> --git <repository> [--path <file>] [--ref <branch>] --public-key <key> [--yes]
```

| Flag | Meaning |
| --- | --- |
| `--public-key <key>` | The base64 ed25519 key the catalog must be signed with. Required. |
| `--git <repository>` | Read the catalog from a git repository instead of a URL, with your own git credentials. |
| `--path <file>` | The catalog's path in the repository. Default `team.yaml`. |
| `--ref <branch>` | Branch or tag to read. Default: the repository's default branch. |
| `-y`, `--yes` | Follow the team without asking. Needed without a terminal. |

### tug team sync

Fetch every team's catalog, or the ones named, and apply new versions after
showing what they change. Your own entries win, and conflicts are listed. A
catalog that cannot be fetched or checked leaves the last good version in
place. Exits 1 when a team could not be checked, or a new version needs a
review nobody can give without a terminal.

```bash
tug team sync [team...] [--yes]
```

### tug team ls

List the teams you follow: where each catalog is, the version you have, when
it was last checked, and whether it is set in `config.yaml` or with
`tug team add`. `-o json|yaml|name` as for `tug ls`.

### tug team show

Show a team's catalog as last accepted, the clusters it names here, its
policies and plugin indexes, and the conflicts with your own entries.
Works offline.

```bash
tug team show <team> [-o json|yaml]
```

### tug team remove

Stop following a team. Its policies and plugin indexes stop applying, and
its names, aliases and labels come off your clusters, which keep their
names. Accounts it added stay as yours; `tug forget` removes them.

```bash
tug team remove <team>
```

### tug team keygen, sign and verify

For whoever publishes a catalog.

```bash
tug team keygen [--name default]            # prints the public key; the private key stays in the credential store
tug team sign team.yaml [--name default]    # checks the catalog and writes team.yaml.sig
tug team verify team.yaml --public-key <key>
```

In CI, set `TUG_TEAM_KEY` to the private key instead of using the credential
store.
