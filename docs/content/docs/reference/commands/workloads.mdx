Every command here takes a [target](/docs/concepts/targets): a fuzzy name such
as `api`, or a kind and name such as `sts/db` or `pod/debug`. All accept
`-n`, `--namespace` to look outside the session's namespace. Commands that
change the cluster ask first on a [read-only session](/docs/concepts/read-only).

## tug logs

Tail logs from every pod of a workload, with coloured `pod/container` prefixes.

```bash
tug logs <target> [flags]
```

| Flag | Meaning |
| --- | --- |
| `-f`, `--follow` | Keep streaming, including pods that start later. |
| `-c`, `--container <name>` | Only this container. |
| `--tail <n>` | Lines from the end of each log. Default: all for a pod, 10 for a workload. |
| `--since <duration>` | Only lines newer than this, such as `10m`. |
| `-p`, `--previous` | Logs of the previous container instance. |
| `--timestamps` | Include timestamps. |
| `--json` | Pretty-print lines that are JSON objects. |

```bash
tug logs api -f
tug logs sts/db -c postgres --since 10m
tug logs api --json
```

## tug sh

Open a shell (bash, else sh) in a pod, or run a command. For a workload, tug
picks a running, ready pod. The command's exit code is passed back.

When the container has no shell, as in distroless images, tug offers to add an
ephemeral debug container that shares its processes; the container's files are
under `/proc/1/root`. Adding one is a write, and it stays until the pod is
replaced.

```bash
tug sh <target> [-- command...] [flags]
```

| Flag | Meaning |
| --- | --- |
| `-c`, `--container <name>` | Container. Default: the pod's default container. |
| `--image <image>` | Image of the debug container offered when the container has no shell. Default: `busybox:1.36`. |

```bash
tug sh api
tug sh api -c sidecar
tug sh api -- env
```

## tug pf

Port-forward to a workload by short name. Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop.

```bash
tug pf <target> [[local:]port...] [flags]
```

| Flag | Meaning |
| --- | --- |
| `--address <addr>` | Addresses to listen on. Default: `localhost`. Repeat or comma-separate for several. |
| `--name <name>` | Run in the background through tugd under this name, reconnecting when the pod goes away. |

```bash
tug pf api 8080          # localhost:8080 → container port 8080
tug pf api 9000:http     # localhost:9000 → the port named http
tug pf db                # every declared port to the same local port
tug pf db 5432 --name db # in the background, through tugd
```

| Subcommand | Meaning |
| --- | --- |
| `tug pf ls [-o table\|json\|yaml\|name]` | List the named forwards tugd keeps open, with their profile, state, restarts and, while reconnecting, when they retry. Alias: `list`. |
| `tug pf stop <name>... \| --all` | End named forwards. |
| `tug pf profile up <name>` | Start a [profile](/docs/guides/profiles)'s forwards that aren't running. Every local port is checked first, and none start when one is taken. |
| `tug pf profile down <name>` | Stop a profile's forwards, including ones since removed from its file. |
| `tug pf profile ls [name] [-o …]` | List a profile's forwards and how they are doing, or every profile's. |

tugd starts a named forward that drops again on a running pod, on the same
local ports, after 1 second and then up to 30 seconds apart. A workload called
`ls`, `stop` or `profile` is `deploy/ls`, `deploy/stop` or `deploy/profile`.

## tug restart

Rolling-restart a deployment, statefulset or daemonset.

```bash
tug restart <target>
```

## tug scale

Set the replicas of a deployment or statefulset.

```bash
tug scale <target> <replicas>
```

```bash
tug scale api 3
tug scale worker 0
```

## tug rollback

Roll a deployment back to its previous revision, or a chosen one.

```bash
tug rollback <target> [--to-revision <n>]
```

| Flag | Meaning |
| --- | --- |
| `--to-revision <n>` | Revision to return to. Default: the previous one. |

## tug top

Show CPU and memory of a workload's pods, or every pod in the namespace. Uses
`kubectl top`, so the cluster needs metrics-server.

```bash
tug top [target]
```

## tug why

Explain why a deployment, statefulset, daemonset, job or pod isn't ready, and
what to do next: crashes (with the last exit code), image pulls, out-of-memory
kills, missing ConfigMaps or Secrets, failing probes, scheduling, volume claims
and recent warning events.

Any other kind works too, named as kubectl names it: a custom resource, a
cronjob, a node. tug reads its status conditions, checks that its controller
has caught up with its latest change, and looks at everything it owns, with the
diagnosis above for each workload it owns. It only reads, and never reads a
Secret's data. See
[Why isn't it working?](/docs/guides/workloads#why-isnt-it-working).

```bash
tug why <target> [-o table|json|yaml]
```

```bash
tug why api
tug why sts/db -n data
tug why job/migrate -o json
tug why certificate/web-tls
tug why kustomization.kustomize.toolkit.fluxcd.io/apps -n flux-system
```

## tug tree

Show a workload's ownership tree with the health of each part: ReplicaSets or
revisions, pods and containers, the Services that select the pods, and the
ConfigMaps, Secrets and volume claims they use. For any other kind, show
everything it owns through ownerReferences, with each workload it owns shown
the same way. It only reads, and shows only the key names of Secrets.

```bash
tug tree <target> [-o table|json|yaml]
```

```bash
tug tree checkout
tug tree cronjob/nightly-backup
```

## tug check

Check the workloads and other objects in a namespace, in every namespace, or
one target, against policy packs: resource requests and limits, probes, a
non-root user, allowed image registries and storage classes,
PodDisruptionBudgets, topology spread, labels, annotations, and conditions a
custom resource must have. Findings are written as `tug why` writes them. tug
has one pack built in, `baseline`, whose checks are all advisory; others come
from `policy.packs` in config.yaml. check exits 1 only when a blocking check
fails. It only reads, and never reads a Secret's data. See
[Policy packs](/docs/guides/policy).

```bash
tug check [target] [-n namespace | -A] [--pack name]... [-o table|json|yaml]
tug check --list [--pack name]...
```

| Flag | What it does |
| --- | --- |
| `-n`, `--namespace` | The namespace to check. Default: the session's. |
| `-A`, `--all-namespaces` | Check every namespace, and the kinds that aren't namespaced. |
| `--pack <name>` | Run this pack (repeatable). Default: the packs `policy.default` names, or all. |
| `-o`, `--output` | `table`, `json` or `yaml`. |
| `--list` | List the packs check would run and their checks, without reading the cluster. |

```bash
tug check
tug check -A --pack platform
tug check deploy/api -o json
tug check certificate/web-tls
tug check --cluster-selector env=prod --pack platform
```

## tug watch

Follow a workload's rollout, or any object's reconciliation, as it happens: one
line for each meaningful change to the object and to everything it owns, as
`tug tree` finds it. Lines report conditions changing status or reason, a new
generation of the spec and the controller catching up with it, replica counts,
pods' status, restarts and scheduling failures, and objects appearing, becoming
ready or not ready, terminating and being deleted. `--events` adds new warning
events about any of it. Ctrl-C ends it.

`--until ready` exits 0 once the object is ready: a workload rolled out, a job
complete, a pod ready, or any other object ready by its conditions. It exits 1
when that cannot happen as things are, such as a failed job or a deployment
past its progress deadline, and when `--timeout` passes first. `--until
deleted` waits for the object to be gone. `-o json` writes one JSON object per
change. It only reads, and never reads a Secret's data. See
[Watch it change](/docs/guides/workloads#watch-it-change).

```bash
tug watch <target> [--events] [--until ready|deleted] [--timeout 5m] [-o table|json]
```

```bash
tug watch api
tug watch deploy/api --until ready --timeout 5m
tug watch certificate/web-tls --events
tug watch job/migrate --until ready -o json
tug watch pod/api-7d9f-x2x4z --until deleted
```

## tug support bundle

Collect diagnostic evidence about an object, or with `namespace/<name>` a whole
namespace, into a redacted `.tar.gz` archive: the object and what it owns as
YAML, `tug why` and `tug tree` as JSON, events, container logs (current and
previous), the conditions of the nodes its pods run on, the cluster's version
and resources, `tug doctor`'s checks, a `manifest.json` of every file and where
it came from, and a `README.md` that says what was redacted and how to review
it. It only reads. See
[Send it to someone who can help](/docs/guides/workloads#send-it-to-someone-who-can-help).

```bash
tug support bundle <target> [--since 1h] [--output <file>|-] [--preview]
  [--include <kind>]... [--exclude <kind>]... [--logs-tail 1000]
  [--redact-pattern <regex>]...
```

| Flag | Meaning |
| --- | --- |
| `-n`, `--namespace` | Namespace of the target (default: the session's). |
| `--since` | How far back events and current logs go (default `1h`). |
| `--output` | File to write, or `-` for stdout (default `./tug-bundle-<cluster>-<target>-<time>.tar.gz`). An existing file is never replaced. |
| `--preview` | List the files that would be written, with their sizes and sources, and write nothing. |
| `--include` | Collect only objects of this kind, as kubectl names it (repeatable). Events are kind `event` and nodes kind `node`. |
| `--exclude` | Leave objects of this kind out (repeatable). |
| `--logs-tail` | Most lines kept from the end of each log (default `1000`); `0` leaves logs out. |
| `--redact-pattern` | Also redact whatever this regular expression matches (repeatable). |

Redaction is always on: Secrets are copied as metadata only; environment
variable values, ConfigMap values, fields named like a credential and the
`kubectl.kubernetes.io/last-applied-configuration` annotation are replaced with
`<redacted>`; and bearer and basic credentials, passwords in URLs, JSON Web
Tokens, PEM private keys, AWS access key IDs, GitHub, GitLab and Slack tokens
and `key=value` credentials are redacted in logs, events and every other text.
The archive's mode is `0600`. The path goes to stdout, progress to stderr.

```bash
tug support bundle deploy/api
tug support bundle certificate/web-tls -n ingress
tug support bundle namespace/shop --since 6h
tug support bundle api --preview
tug support bundle api --exclude configmap --redact-pattern 'cust-[0-9]+'
```
