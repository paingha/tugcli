`tug plugin` (alias `tug plugins`) manages [provider plugins](/docs/plugins).

## tug plugin ls

List providers, built in and plugins, with each plugin's pinned version
(`PINNED`). Alias: `list`. Warns on stderr about installed plugins that a
configured index has [revoked](/docs/plugins/indexes#revoking-a-release),
and about pins to versions that are not installed.

```bash
tug plugin ls
```

```console
$ tug plugin ls
```

## tug plugin describe

Run a plugin's `describe` operation and show its manifest.

```bash
tug plugin describe <name>
```

## tug plugin inspect

Explain what a plugin may access, without installing or running it: the
secrets it would receive, its environment variables, network hosts, files,
sockets and programs, whether it would run in the sandbox, its CPU, memory
and time limits after `plugins.limits`, who signed it, whether an index has
revoked it, and whether it is pinned.

```bash
tug plugin inspect <archive|url|name[@version]> [-o table|json|yaml] [--sha256 <hash>]
```

```bash
tug plugin inspect ./tug-provider-acme_0.1.0.tar.gz   # an archive, matched to its index entry by sha256
tug plugin inspect acme@0.2.0                         # downloaded from an index and checked, not installed
tug plugin inspect acme -o json                       # an installed or linked plugin, from its install receipt
```

A name without a version is the installed or linked plugin when there is
one, and otherwise the pinned version, or the newest, in the indexes. `--sha256` checks an
archive from a URL. The JSON and YAML are stable for review scripts.

## tug plugin search

Search the signed plugin indexes in `plugins.indexes` by name, description or
publisher. With no query, list everything. See [Plugin indexes](/docs/plugins/indexes).

```bash
tug plugin search [query] [-o table|json|yaml|name]
```

## tug plugin install

Install a plugin by name from a signed index, or from a `.tar.gz` or `.zip`
archive, after checking its checksums. Shows the publisher, secrets,
environment, network hosts, sandbox and limits first, and asks to confirm.
Refuses an archive that a configured index has revoked, and a version other
than the plugin's pin in `plugins.pins`; a pinned plugin named without a
version installs at its pin.

```bash
tug plugin install <name[@version]|file|url> [flags]
```

```bash
tug plugin install acme                 # newest version from the first index that has it
tug plugin install acme@0.1.0
tug plugin install ./tug-provider-acme_0.1.0.tar.gz
tug plugin install https://example.com/tug-provider-acme_0.1.0.tar.gz --sha256 9f2c…
tug plugin install acme@0.1.0 --pin           # and pin acme to 0.1.0 in config.yaml
```

| Flag | Meaning |
| --- | --- |
| `--sha256 <hash>` | Expected SHA-256 of the archive. Required for URLs; an index supplies it for names. |
| `-y`, `--yes` | Install without asking. |
| `--force` | Replace the same version if it's installed. |
| `--pin` | Pin the plugin to the version installed, in `plugins.pins` in `config.yaml`, replacing any pin it has. |

## tug plugin link

Use a plugin folder you're developing. No checksums; marked `dev plugin`.

```bash
tug plugin link <dir>
```

## tug plugin unlink

Stop using a linked plugin.

```bash
tug plugin unlink <name>
```

## tug plugin remove

Remove every installed version of a plugin. Aliases: `rm`, `uninstall`.

```bash
tug plugin remove <name>
```

## tug plugin new

Start a new plugin with the SDK, tests and a release workflow.

```bash
tug plugin new <name> [flags]
```

```console
$ tug plugin new acme
  created tug-provider-acme/go.mod
  created tug-provider-acme/main.go
  created tug-provider-acme/main_test.go
  created tug-provider-acme/plugin.yaml
  created tug-provider-acme/Makefile
  created tug-provider-acme/.gitignore
  created tug-provider-acme/.github/workflows/release.yml
  created tug-provider-acme/README.md

Next:
  cd tug-provider-acme
  go mod tidy && make test && make conformance
go mod tidy fetches the SDK, github.com/paingha/tugcli. If you cannot reach it, set GOPRIVATE=github.com/paingha/tugcli with access to the repository, or scaffold again with --sdk-replace <tugcli checkout>.
```

| Flag | Meaning |
| --- | --- |
| `--lang <go\|python>` | Language. Default: `go`. |
| `--module <path>` | Go module path. Default: `example.com/tug-provider-<name>`. |
| `--dir <dir>` | Folder to create. Default: `./tug-provider-<name>`. |

## tug plugin package

Write an installable archive, recording each binary's SHA-256 in its manifest.

```bash
tug plugin package [dir] [-o dist]
```

| Flag | Meaning |
| --- | --- |
| `-o`, `--output <dir>` | Folder to write the archive to. Default: `dist`. |

## tug plugin test

Run the [conformance suite](/docs/plugins/testing) against a plugin or a
built-in provider.

```bash
tug plugin test <name> [flags]
```

```console
$ tug plugin test kubeconfig --account default
RESULT   CHECK                                  DETAIL
pass     describe is valid                      kubeconfig v0.2.0-23-ge1e7155 (Clusters in kubeconfig files (~/.kube/config, $KUBECONFIG, or files you name)) speaks [provider/v1alpha1]
pass     unknown operations are rejected        exit 2, InvalidConfig
pass     an empty list request is rejected      exit 1, InvalidConfig
pass     list returns valid clusters            2 clusters
pass     list is stable across calls            same 2 ids
pass     credential is valid and unexpired      cluster prod-eu: clientCert, expires 2027-11-22T22:42:22Z
skip     invalid secrets give Unauthenticated   the plugin declares no secrets
pass     accounts is valid                      1 account
pass     SIGTERM stops the plugin promptly      exited within 2s
pass     stdout carries only one JSON object    7 calls
pass     serve answers like one-shot mode       answered 5 requests by ID and exited when stdin closed

10 passed, 1 skipped, 0 failed
```

| Flag | Meaning |
| --- | --- |
| `--account <id>` | Imported account to test against. |
| `--set key=value` | Account setting. Repeatable. |
| `-o`, `--output <format>` | `table` or `json`. |

## tug plugin index

Build and sign a plugin index, for those who publish one. See
[Publishing an index](/docs/plugins/indexes#publishing-an-index).

| Command | Meaning |
| --- | --- |
| `tug plugin index keygen [--name <key>] [--force]` | Make an ed25519 signing key, kept in the credential store, and print its public key. |
| `tug plugin index add <index.yaml> <archive> --url <https URL> [--description <text>]` | Record a packaged archive in an index file, creating the file if needed. |
| `tug plugin index revoke <index.yaml> <archive\|sha256> [--reason <text>]` | Withdraw an archive: install refuses it and `tug plugin ls` warns those who have it. `--plugin` and `--version` name an archive the index never listed. |
| `tug plugin index rotate <index.yaml> --to <key> [--from <key>]` | Hand the index over from its signing key (`--from`, default `default`, or `TUG_INDEX_KEY`) to a new one from `keygen --name`; then sign with the new key. |
| `tug plugin index sign <index.yaml> [--name <key>]` | Sign the index, writing `<index.yaml>.sig`. `TUG_INDEX_KEY` supplies the key in CI. |
| `tug plugin index verify <index.yaml> --public-key <key>` | Check an index against its signature and public key. |
