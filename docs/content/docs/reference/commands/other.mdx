## tug auth

Sign in, rotate credentials, and serve them to kubectl and other clients.

### tug auth login

Sign in to the OpenID Connect issuer a cluster trusts, in your browser or with
a device code. Without a cluster, signs in for this terminal's cluster. See
[Signing in with OpenID Connect](/docs/guides/sign-in).

```bash
tug auth login [cluster] [label=value...] [--device]
```

| Flag | Meaning |
| --- | --- |
| `--device` | Show a code to enter on another device instead of opening a browser here. Automatic over SSH. |

### tug auth logout

Forget the OpenID Connect sign-in a cluster uses. Every cluster sharing that
sign-in needs `tug auth login` again. The issuer isn't told.

```bash
tug auth logout [cluster] [label=value...]
```

### tug auth rotate

Replace a cluster's credential with a new one, which the provider issues while
revoking the old. Only providers with the `rotate` capability can do this. See
[Rotating a credential](/docs/guides/rotating).

```bash
tug auth rotate [cluster] [label=value...] [--yes]
```

| Flag | Meaning |
| --- | --- |
| `-y`, `--yes` | Rotate without asking. Read-only clusters still ask. |

The commands below are what kubectl and other clients call through the
kubeconfigs tug writes. You won't usually run them yourself.

### tug auth token

Print a `client.authentication.k8s.io/v1` ExecCredential for a cluster. It
answers from the cache, or asks the cluster's provider on a miss.

```bash
tug auth token --cluster <id> [--refresh]
```

| Flag | Meaning |
| --- | --- |
| `--cluster <id>` | Catalog cluster ID or name. Required. |
| `--refresh` | Ignore the cache and ask the provider. |

### tug auth proxy-token

Print an ExecCredential for a session's [tugd](/docs/guides/proxy) proxy. Used
by sessions connected with `--proxy`.

## tug daemon

Run tugd, the background process behind the [local API proxy](/docs/guides/proxy).
tug starts it when a session needs it, and it stops after 30 minutes without a
live session or a named port-forward.

| Command | Meaning |
| --- | --- |
| `tug daemon start` | Start tugd in the background if it isn't running. |
| `tug daemon status [-o table\|json\|yaml]` | Show whether it's running and what it serves. |
| `tug daemon stop` | Stop tugd. |

## tug intelligence

Set up the model providers behind [`tug why --deep`](/docs/guides/ai-explanations),
and see what they cost.

| Command | Meaning |
| --- | --- |
| `tug intelligence enable [provider] [--model <id>] [--base-url <url>]` | Turn `--deep` on with anthropic, openai, mistral or custom, and, on a terminal, ask for and store its API key when none is stored. Another provider goes back to its own model and address unless the flags say otherwise. |
| `tug intelligence disable` | Turn `--deep` off, keeping the other settings, the ledger and stored keys. |
| `tug intelligence status [-o table\|json\|yaml]` | The provider, model and address `--deep` uses, where its key comes from (never the key), the price that applies, and this month's spend. |
| `tug intelligence usage [--limit <n>] [-o table\|json\|yaml]` | The latest calls, and their tokens and cost by day and month (UTC). |
| `tug intelligence key set <provider>` | Ask for a provider's API key on the terminal and keep it in the keychain. |
| `tug intelligence key rm <provider>` | Remove a provider's stored key. |
| `tug intelligence models [-o table\|json\|yaml\|name]` | Each provider's default model, and the prices tug assumes, with their sources. |

## tug settings

Read and change [config.yaml](/docs/reference/configuration) without editing
it. tug changes only what you name, so the rest of the file, comments included,
stays as you wrote it (blank lines between settings do not survive), and it
refuses a value it could not use: a provider it does not know, a plugin index
key that is not ed25519, an `http` address that is not on this machine, a word
where a number belongs. Secrets are never settings.

A setting is one of:

- **one value**, such as `intelligence.enabled` or `sessions.maxAge`, changed
  with `set` and `unset`;
- **an entry of a map**, named after it: `plugins.timeouts.<operation>` or
  `plugins.pins.<plugin>`, changed with `set` and `unset`;
- **a list**, changed one item at a time with `add` and `remove`: a list of
  names (`plugins.sandbox.exclude`, `plugins.allowOverride`,
  `oidc.listenAddresses`, `policy.default`), of label sets
  (`guard.readOnlyLabels`), or of entries with named fields (`plugins.indexes`,
  `intelligence.prices`, `policy.packs`). Give a label set or an entry as
  `key=value` arguments. Adding an entry with the name, model, path or url of
  one already there replaces it; `remove` takes the entry's name, model, path
  or url alone. `unset` removes a whole list, and a list left empty goes, so
  tug uses its default again.

| Command | Meaning |
| --- | --- |
| `tug settings list [-o table\|json\|yaml\|name]` | Every setting, the value tug uses, and where it comes from: config.yaml, a variable such as `TUG_KUBECTL`, or tug's default. |
| `tug settings get <setting>` | Print the value tug uses; a list's items one a line, as `add` takes them. |
| `tug settings set <setting> <value> [-y]` | Change a setting, or an entry of a map. Booleans take `true` or `false`, durations take `30s` or `5m`. |
| `tug settings unset <setting> [-y]` | Remove a setting, an entry of a map or a whole list, so tug uses its default. |
| `tug settings add <setting> <item...> [-y]` | Add an item to a list. |
| `tug settings remove <setting> <item...> [-y]` | Remove an item from a list. |
| `tug settings path` | Print where config.yaml is. |

A change that makes tug trust something or protect less is shown, and asked
about, before it is made: trusting a plugin index, running a plugin without
the sandbox or turning the sandbox off, letting a plugin replace a built-in
provider, no longer requiring Sigstore signatures, raising a plugin limit, or
a cluster no longer opening read-only. Without a terminal it is refused unless
`-y`/`--yes` is given.

The first label set added to `guard.readOnlyLabels` keeps `env=prod` with it,
because tug's default of `env=prod` applies only while the list is empty: a
list of your own would otherwise stop production clusters opening read-only.

```bash
tug settings set intelligence.monthlySpendCapUSD 20
tug settings add guard.readOnlyLabels team=payments tier=critical
tug settings add plugins.indexes name=acme url=https://plugins.acme.example/index.yaml publicKey=<key>
tug settings add policy.packs url=https://policy.acme.example/pack.yaml sha256=<sha256>
tug settings add policy.default acme
tug settings add intelligence.prices model=llama4 input=0 output=0
tug settings set plugins.timeouts.list 60s
tug settings unset plugins.pins.digitalocean      # unpin a plugin
tug settings remove plugins.indexes acme
```

[Team catalogs](/docs/guides/teams) are followed with `tug team add` and
`tug team remove`, not with `tug settings`.

## tug version

Print tug's version, commit, Go version and platform.

```bash
tug version [-o table|json|yaml]
```

## tug completion

Generate a tab-completion script. See
[Installation](/docs/getting-started/installation#turn-on-tab-completion-optional).

```bash
tug completion <bash|zsh|fish|powershell>
```
