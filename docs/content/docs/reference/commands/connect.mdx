## tug connect

Point this terminal at a cluster. Other terminals and `~/.kube/config` are not
touched. Alias: `tug c`.

```bash
tug connect [cluster] [label=value...] [flags]
```

The cluster can be a full name, a prefix or a [fuzzy match](/docs/concepts/targets).
`label=value` arguments filter first. With no arguments, tug shows a list.
Clusters labelled `env=prod` open [read-only](/docs/concepts/read-only).

| Flag | Meaning |
| --- | --- |
| `-n`, `--namespace <name>` | Namespace for this session. |
| `--read-only` | Open read-only, whatever the cluster's labels. |
| `--read-write` | Open read-write, even on a production cluster. |
| `--proxy` | Go through [tugd](/docs/guides/proxy), so the guard applies to every client. |

```bash
tug connect staging
tug connect prod -n payments --proxy
tug connect gpu=true
```

```console
$ tug connect staging-us -n shop
Connected to staging-us, namespace shop, read-write
$ tug connect prod-eu -n shop
Connected to prod-eu, namespace shop, read-only (tug unlock 15m to allow writes)
```

## tug disconnect

Stop pointing this terminal at a cluster. `KUBECONFIG` goes back to what it
was before.

```bash
tug disconnect
```

## tug status

Show this terminal's cluster, namespace and mode. Alias: `tug current`.

```bash
tug status [-o table|json|yaml|name]
```

```console
$ tug status
cluster:    staging-us
namespace:  shop
mode:       read-write
kubeconfig: /run/user/1000/tug/sessions/feae99b08267/kubeconfig
env:        staging
```

`-o name` prints just the cluster name, which is handy in prompts and scripts.
JSON fields: `session`, `cluster`, `clusterID`, `namespace`, `readOnly`,
`writable`, `unlockedUntil`, `kubeconfig`, `proxyURL`, `env` (the cluster's env
label), `production` (its labels make it read-only, whatever the session's
mode) and `profile` (the [profile](/docs/guides/profiles) it was connected
with).

## tug ns

Switch this session's namespace. The name is matched fuzzily.

```bash
tug ns [namespace]
```

```console
$ tug ns kube-sys
Namespace kube-system on staging-us
```

With no name, tug shows a list in a terminal, or prints all namespaces (the
current one marked `*`) in a script. If you aren't allowed to list namespaces,
tug trusts the name you give.

## tug shell

Start a subshell with its own session, for shells or environments without the
hook. Takes the same cluster arguments as `connect`. Type `exit` to leave.

```bash
tug shell [cluster] [label=value...] [flags]
```

```console
$ tug shell prod-eu
Connected to prod-eu, namespace default, read-only (tug unlock 15m to allow writes)
```

| Flag | Meaning |
| --- | --- |
| `-n`, `--namespace <name>` | Namespace for the new session. |
| `--read-only` | Open read-only, whatever the cluster's labels. |
| `--read-write` | Open read-write, even on a production cluster. |

## tug init

Print the shell hook. See [Set up your shell](/docs/getting-started/shell-setup).

```bash
tug init <zsh|bash|fish|powershell>
```

Set `TUG_PROMPT_DISABLE=1` to keep your prompt unchanged.

## tug ui

Open a full-screen terminal UI on this terminal's session: the catalog's
clusters, and the namespace's workloads with their health. Logs, why, tree,
shells, port-forwards, restarts and scaling are one key away, and on a
read-only session writes ask first. See [the terminal UI](/docs/guides/tui).

```bash
tug ui [--k9s] [-- k9s arguments...]
```

| Flag | Meaning |
| --- | --- |
| `--k9s` | Open [k9s](https://k9scli.io) with the session's kubeconfig instead. Arguments after `--` go to k9s. |

`tug ui` needs a terminal.

```bash
tug ui
tug ui --k9s -- --readonly
```

## tug doctor

Check tug's setup and one cluster: DNS, TCP, TLS, credentials, the API server,
clock and version skew, identity, permissions and the provider's access list.
It only reads, and exits 1 when a check fails. See the
[troubleshooting guide](/docs/guides/doctor).

```bash
tug doctor [cluster] [flags]
```

```console
$ tug doctor

                                      fix: `tug ls` marks them stale; `tug forget <provider>/<account>` removes a source you no longer use

```

| Flag | Meaning |
| --- | --- |
| `--egress-ip <ip>` | Your public IP, for providers that check access lists. |
| `-o`, `--output <format>` | `table`, `json` or `yaml`. |

## tug pin

Pin a directory, and everything below it, to a cluster and namespace with a
`.tug.yaml` file. See [Directory pins](/docs/guides/pins).

| Command | Meaning |
| --- | --- |
| `tug pin set <cluster> [label=value...] [-n <ns>] [--dir <dir>]` | Write `.tug.yaml`, allow it and apply it to this terminal. `--dir` defaults to the current folder; `-n` to the cluster's default namespace. |
| `tug pin show [dir]` | Show the pin that applies to a folder and whether it's allowed. |
| `tug pin allow [dir]` | Trust the pin file as it is now. |
| `tug pin revoke [dir]` | Stop trusting it. Alias: `deny`. |

Set `TUG_PIN_DISABLE=1` to turn pins off in a shell.

```console
$ tug pin set staging-us -n shop
Wrote ~/src/shop/.tug.yaml: staging-us, namespace shop
pinned by ~/src/shop/.tug.yaml: staging-us, namespace shop
$ tug pin show
~/src/shop/.tug.yaml
  pins:  staging-us, namespace shop
  state: allowed, and this terminal is pinned by it
```

## tug profile

Switch a terminal to a saved working environment: a cluster, namespace, safety
mode, command aliases and port-forwards, from a YAML file in tug's config
folder. See [Profiles](/docs/guides/profiles).

| Command | Meaning |
| --- | --- |
| `tug profile use <name>` | Connect this terminal as the profile says. |
| `tug profile up <name>` | Connect, and start the profile's port-forwards through tugd. |
| `tug profile down <name>` | Stop the profile's port-forwards. The terminal stays connected. |
| `tug profile ls [-o table\|json\|yaml\|name]` | List profiles; `*` marks this terminal's. Alias: `list`. |
| `tug profile show [name] [-o …]` | Show a profile, by default this terminal's, and how its forwards are doing. |
| `tug profile edit <name>` | Write or change a profile in `$VISUAL` or `$EDITOR`; it is saved only once it parses. Without a terminal, reads the profile from stdin. |
| `tug profile run <alias> [args...]` | Run an alias of this terminal's profile, held to the same guard as the command typed out. |

A profile can make a session read-only (`safety: read-only`) but never
read-write: a cluster whose labels make it read-only still needs confirmation
or `tug unlock` for writes.

```console
$ tug profile up shop
Profile shop: connected to staging-us, namespace shop, read-write
aliases: cache, checkout-logs; tug profile run <alias> runs one
Forwarding localhost:6379 -> 6379 to sts/redis (pod/redis-0) as shop.redis
Forwarding localhost:8080 -> 80 to frontend (pod/frontend-bc79969b9-9nw7c) as shop.web
tugd keeps them open across pod restarts; tug pf profile ls shop shows them, tug profile down shop ends them
$ tug profile show
shop  ~/.config/tug/profiles/shop.yaml  (this terminal's)
  cluster:    staging-us
  namespace:  shop
  safety:     auto: the cluster's labels decide
  proxy:      no
  aliases:
    cache          tug sh sts/redis -- redis-cli info keyspace
    checkout-logs  tug logs checkout -f
  forwards:
      NAME         TARGET      NAMESPACE   PORTS       STATE
      shop.redis   sts/redis   shop        6379:6379   forwarding
      shop.web     frontend    shop        8080:80     forwarding
$ tug profile down shop
Stopped shop.redis
Stopped shop.web
```

## tug tunnel

Reach a private cluster through an SSH jump host, a proxy, AWS Systems Manager
or Google Cloud IAP. See [Reaching private clusters](/docs/guides/tunnels).

| Command | Meaning |
| --- | --- |
| `tug tunnel set <cluster> <tunnel>` | Reach the cluster through the tunnel from now on. |
| `tug tunnel test [cluster]` | Open the tunnel and reach the API server through it. Without a cluster, tests this terminal's. |
| `tug tunnel ls [-o table\|json\|yaml\|name]` | List clusters reached through tunnels. Alias: `list`. |
| `tug tunnel rm <cluster>` | Reach the cluster directly again. Alias: `unset`. |

Tunnel addresses:

```text
ssh://[user@]host[:port][?identity=<key file>]
socks5://host:port
http://host:port
ssm://<instance id>[?region=<region>&profile=<profile>]
iap://<instance>?project=<project>&zone=<zone>
iap://?project=<project>&region=<region>&network=<network>&group=<group>
```
