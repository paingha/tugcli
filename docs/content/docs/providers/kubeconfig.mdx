The `kubeconfig` provider reads the kubeconfig files you already have and adds
one cluster to the catalog **for each context** in them. It only ever reads
the files.

## Which files it finds

`tug import` (or `tug import kubeconfig`) looks at:

- `~/.kube/config`
- every file listed in `$KUBECONFIG`
- other `*.yaml`, `*.yml` and `*.kubeconfig` files directly inside `~/.kube`

Each file is its own account:

| File | Account |
| --- | --- |
| `~/.kube/config` | `default` |
| `~/.kube/lke-prod.yaml` | `lke-prod` |
| `~/Downloads/Team Config.yml` | `team-config` |

If two files would get the same name, the second gets `-2`, and so on.

## Importing a file you name

```bash
tug import kubeconfig ~/Downloads/cluster.yaml
tug import kubeconfig ./a.yaml ./b.yaml
tug import kubeconfig ./cluster.yaml --account acme-staging
```

`--account` sets the name when you import a single file.

## What happens to credentials

| In the file | What tug does |
| --- | --- |
| A token or client key written into the file | Copies it into your keychain. Kubeconfigs tug writes never contain it. |
| A `tokenFile` or certificate **path** | Reads the file when needed, and re-reads it at least hourly, so rotated files are picked up. |
| An `exec` plugin (`aws eks get-token`, `gke-gcloud-auth-plugin`, `kubelogin` and so on) | Runs the same plugin, unchanged, when a credential is needed. |
| `insecure-skip-tls-verify: true` | Respected, but [`tug doctor`](/docs/guides/doctor) warns about it. |

After importing a downloaded file, you can delete it: its token lives on in
the keychain. Keep it if you want `tug sync` to pick up changes to it.

## Local clusters

Contexts that belong to local tools (kind, k3d, minikube, Docker Desktop,
OrbStack and Rancher Desktop) are left out of files tug **finds** on its own,
because the [local provider](/docs/providers/local) handles them better. Files
you **name** on the command line import every context.

## Settings

| Setting | Meaning |
| --- | --- |
| `path` | The kubeconfig file. Set for you on import. |
| `skipLocal` | `true` to leave out local clusters' contexts. Set for you on files tug finds. |
