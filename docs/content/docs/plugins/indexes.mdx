A **plugin index** is a file listing reviewed plugins, with the address and
SHA-256 of each archive. The whole file is signed with an ed25519 key, so when
you install by name, tug checks three things before anything runs: the index's
signature, the archive's SHA-256, and the SHA-256 of every binary inside it.

## Using an index

Add the index with the public key its publisher gives you. tug shows what it
will trust and asks first (`--yes` in scripts):

```bash
tug settings add plugins.indexes name=acme url=https://plugins.acme.example/index.yaml publicKey=<the base64 key the publisher printed>
```

That writes it to [`config.yaml`](/docs/reference/configuration#plugins), which
you can also edit by hand:

```yaml title="~/.config/tug/config.yaml"
plugins:
  indexes:
  - name: acme
    url: https://plugins.acme.example/index.yaml
    publicKey: <the base64 key the publisher printed>
```

`tug settings remove plugins.indexes acme` stops trusting it.

Then:

```bash
tug plugin search                # everything in your indexes
tug plugin search gpu            # plugins whose name, description or publisher matches
tug plugin install acme          # the newest version, from the first index that has it
tug plugin install acme@0.1.0    # a particular version
```

`tug plugin search` lists each plugin's name, version, publisher, description
and index. Indexes are searched in the order you list them.

<Callout type="info" title="No default index yet">
  tug comes without an index until one is published. Until then, add the
  indexes you trust yourself, and install first-party plugins from
  [tug's releases](/docs/providers).
</Callout>

## Publishing an index

Anyone can run an index, for a team or a company's internal plugins. You need
the plugin archives (made with [`tug plugin package`](/docs/plugins/writing#package-it))
published somewhere over HTTPS, such as GitHub releases.

<Steps>
<Step>

### Make a signing key, once

```bash
tug plugin index keygen
```

This prints the **public key** your users put in their `config.yaml`. The
private key stays in tug's credential store. Keep a copy somewhere safe: an
index signed with a lost key can only be replaced by a new key that every user
configures again.

</Step>
<Step>

### Add each released archive

```bash
tug plugin index add index.yaml dist/tug-provider-acme_0.1.0.tar.gz \
  --url https://github.com/acme/tug-provider-acme/releases/download/v0.1.0/tug-provider-acme_0.1.0.tar.gz \
  --description "Acme Kubernetes clusters"
```

tug reads the plugin's name and version from the archive, records its
SHA-256, and creates `index.yaml` if it doesn't exist yet.

</Step>
<Step>

### Sign and publish

```bash
tug plugin index sign index.yaml      # writes index.yaml.sig
tug plugin index verify index.yaml --public-key <your public key>   # check before you publish
```

Publish `index.yaml` and `index.yaml.sig` side by side over HTTPS. In CI, give
`tug plugin index sign` the private key through the `TUG_INDEX_KEY`
environment variable instead of the credential store.

</Step>
</Steps>

Sign the index again every time you add a plugin: tug refuses an index whose
signature doesn't match.

## Revoking a release

If a release turns out to be malicious, or to leak secrets, withdraw it and
sign the index again:

```bash
tug plugin index revoke index.yaml dist/tug-provider-acme_0.3.0.tar.gz --reason "sends tokens to a third party"
tug plugin index sign index.yaml
```

You can give the archive's SHA-256 instead of the file. The index then lists
the archive under `revoked`, with its plugin, version and reason, and keeps
the version listed so people can see why it went. tug refuses to install a
revoked archive, by name, from a file or from a URL; installs the newest
version that isn't revoked when no version is given; and warns everyone who
has it installed when they run `tug plugin ls`.

## Changing the signing key

To replace your key, make a new one, hand over to it with the old one, and
sign with the new one:

```bash
tug plugin index keygen --name 2027
tug plugin index rotate index.yaml --to 2027   # the old key, "default", signs the new one
tug plugin index sign index.yaml --name 2027
```

The index lists the old key under `supersededKeys`, with the new key and the
old key's signature over it. Users whose `config.yaml` still names the old
key keep working: tug follows the handover, checks the index against the new
key, and tells them to update `publicKey`. From then on tug remembers the new
key and refuses an index signed with the old one. Keep the old key's entry in
the index, since it's how users who haven't updated reach the new key.

<Callout type="warn" title="A stolen key needs more than a rotation">
  Whoever has your old key can sign a handover to a key of their own. If the
  key leaked, tell your users the new public key yourself, through a channel
  they trust, and have them put it in `config.yaml`.
</Callout>

Older tug releases refuse an index that uses `revoked` or `supersededKeys`,
rather than install a plugin they were told to refuse.
