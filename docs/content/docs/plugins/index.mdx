A **provider plugin** teaches tug about a new place to find clusters: a cloud,
an internal platform, a team's inventory service. Once installed, it works
exactly like a built-in provider: `tug import <name>`, `tug sync`,
`tug connect` and the rest.

## What a plugin is

A plugin is just a program called `tug-provider-<name>`, plus a small
manifest file called `plugin.yaml`. For each job, tug runs the program with
the job's name as its only argument, writes one JSON request to its input, and
reads one JSON response from its output.

```console
$ echo '{"apiVersion":"provider/v1alpha1","kind":"DescribeRequest"}' | ./tug-provider-acme describe
{"apiVersion":"provider/v1alpha1","kind":"DescribeResponse","name":"acme","protocols":["provider/v1alpha1"],"capabilities":["list","credential"]}
```

That's the whole interface, so you can write a plugin in any language. tug
ships a Go SDK and a Python template to make it quick.

## How tug keeps plugins in check

Plugins handle your credentials, so tug is careful with them:

- **You see what it gets before you install.** `tug plugin install` shows the
  publisher, the secrets the plugin will receive, the environment variables
  it reads and the hosts it talks to, then asks you to confirm.
  `tug plugin inspect` shows the same, and more, without installing anything.
- **Checksums are verified.** The binary for your platform must match the
  SHA-256 in its manifest, at install time and every time it's loaded.
- **Version checks.** A plugin that needs a newer tug (its `minTugVersion`) is
  refused, rather than failing in odd ways later.
- **Archives are checked.** tug refuses archives with links or paths that
  point outside the plugin's folder.
- **A clean environment.** Plugins run with a scrubbed environment: only basics
  such as `PATH`, `HOME` and proxy settings, plus variables the manifest
  declares.
- **Only their own secrets.** A plugin receives only the secrets it declares,
  for the account it's working on.
- **Built-ins can't be replaced by accident.** A plugin named `aws` is ignored
  unless you allow it in [`plugins.allowOverride`](/docs/reference/configuration).
- **Timeouts and limits.** Each call has a time limit (30 seconds to list, 10
  seconds for a credential), after which tug stops the plugin, and
  [`plugins.limits`](/docs/plugins/managing#limits) caps the CPU time and
  memory any plugin gets.
- **Revocations and pins.** An index can revoke a bad release, which tug then
  refuses to install and warns you about if you have it, and you can
  [pin](/docs/plugins/managing#pin-a-version) a plugin to a version you've
  reviewed.
